# Browser viewport preset source review

## Bounded source declaration

The [fixed baseline](browser-viewport-presets-baseline.json) records the module's
explicit source-identical constants/helpers claim. Directory membership and
device names do not select adjacent code for replacement. Preset IDs, dimensions,
order and default state are existing application compatibility data. Retain
them; do not imply these are independently verified physical-device specifications
or remove working device choices because of their brand names.

## Requirements frozen before authoring

- Preserve all six public exports and both current consumers. Initialization
  establishes the default, responsive ID and ordered 13-entry preset catalog;
  repeated initialization retains the same object/array identities.
- Preserve the default disabled responsive state (390 by 844), the exact
  existing application preset data and ordering recorded in the baseline.
  The values are compatibility inputs; their presence alone is not a reason
  to invent different dimensions or add a new device catalog.
- Width/height helpers round to an integer and enforce current bounds (minimum
  240/160, maximum 4096). Preserve pure numeric return behavior, including the
  observed nonfinite propagation, without taking over drag capture, keyboard,
  persistence, scale or Host state.
- Review the explicitly attributed helper expression and initialization only.
  Preserve ordinary data and stable integration names. No new tests/harness,
  no neighboring manager/Host rewrite, no strict author isolation or historical
  rights clearance claim. Public declaration and black-box application outputs
  are authoring inputs; old target expressions are not printed for authoring.

## Initial public observations

Native module observation, outside the repository, records all application
values, undefined data exports before initialization, identity stability after
reinitialization and boundary/fractional/nonfinite numeric calls. The next step
is to complete the frozen public contract observations before authoring a bounded
implementation. This checkpoint contains no implementation change.


## Completed pre-authoring contract review

The declaration and both actual consumers use six exports, while runtime
introspection also found seven undeclared legacy exports: `DEFAULT_DEVICE_PRESET`,
`MAX_DIMENSION_HEIGHT`, `MAX_DIMENSION_PRESET`, `WEBVIEW_PADDING`, `cBr`,
`clampDimension` and `insetDimensions`. Bounded reference search across application,
package, plugin, test and script consumers found no uses outside the target
module. The manager adapter explicitly injects only the declared preset ports.
Remove those unused recovery artifacts rather than retaining a second padding
or color-token owner. This changes the private module's undeclared export list;
all declared/currently consumed APIs and integration behavior must remain.

Freeze the observed 13-entry application data, mutable runtime object identity,
undefined data bindings before initialization, idempotent initialization returning
undefined, and all 6,021 numeric calls. Before initialization the two bound helpers
return NaN; both consumers initialize before use. Preserve that observed behavior
without promoting it as supported UI admission. The external observation digest
is `c66c74c1e230b3024d7c5dbf996844670f7179118c570ca5183406f3eb8a67d2`.

These are application compatibility values, not newly researched hardware facts.
The replacement may represent the same values directly without reproducing the
old helper expressions or initialization scaffolding. No implementation has been
authored at this frozen checkpoint. Remaining neighboring/browser rights and
strict author isolation remain outside the conclusion.


## Implementation and verification

The complete current module represents the observed application catalog directly,
with one idempotent initializer and one private rounded bound helper. It retains
all six declared exports and removes exactly the seven unused, undeclared exports
listed above. The declaration and consumers are unchanged. The historical source
annotation and blob remain in the baseline; this is a current implementation
replacement, not a change to the provenance of historical commits.

External native-module comparison matched all 6,021 numeric calls, catalog values
and order, pre-initialization bindings/NaN, and repeated initialization identities.
Actual toolbar/handle components in Chromium passed all 13 preset choices in
390/1100-wide light/dark scenes (52 selections), five held resize handles in each
scene (20 held-handle sequences), reversal, Escape restoration and keyboard input.
The observer used a local DOM adapter; no native guest or employee session was
verified. A narrow dark screenshot was inspected. No observer or new test harness
is committed to the repository.

The Web typecheck, platform/typography boundaries, 30 existing browser/provenance
tests and source inventory passed. The public Web release build completed with
791 runtime source files and zero compatibility issues. These checks cover the
bounded preset implementation and current consumers, not remaining browser
source areas, strict author isolation, historical rights or legal clearance.
