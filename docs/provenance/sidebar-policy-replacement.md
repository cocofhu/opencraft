# Sidebar presentation policy boundary

## Explicit selection

The historical module header in `apps/workbench-web/src/sidebar-dock-model.ts`
declares restored behavior. The initial recorded module contained only
`resolveSidebarFloatingIntent`, `resolveSidebarPresentation` and
`shouldMountFloatingSidebarPresenceOwner`. Those three declarations are selected;
the later hover capability and toggle-action functions, exported types and
ordinary edge/peek constants retain their exact bytes. A file-level annotation
does not turn later application additions into rewrite targets.

The baseline retains the historical module/declaration hashes and original
annotation. This is a bounded implementation selection, not a determination of
reference rights, a copying finding for every file member or permission to erase
history. Earlier author exposure remains possible; no strict isolation is claimed.

## Requirements frozen before authoring

Preserve all three synchronous, side-effect-free typed APIs. Docked ownership
prevents floating intent. An unacquired pointer can reveal only from the existing
edge contract or the unsuppressed delayed header trigger; acquired intent keeps
the panel's full-width boundary. Freeze null, negative, boundary, fractional and
nonfinite numeric behavior before authoring rather than inventing corrections.

Presentation has one semantic owner: docked layout wins, outgoing layout or
resize ownership finishes before floating takes over, and floating resize can
keep its surface present after requested visibility is withdrawn. The floating
presence owner mounts only after docked layout ownership has ended. Keep exact
state precedence and return strings from complete boolean truth tables.

Shell and the existing intent hook retain pointer acquisition, touch filtering,
timers, suppression, request state, animation, inertness, resize capture and
shared content portals. These pure projections must not create another state
owner or mutate draft, focus, width preference, Host, Thread or navigation.

Before replacing code, freeze complete public outputs and actual legacy AppShell
states including pointer entry/leave, docking, exit reversal, held resize and
content lifetime. Compare full outputs with unchanged observers. Reuse existing
tests and real Web/mobile checks; add no repository tests or harness. Preserve
pre-existing footer/scroll findings and initial authoring failures. Historical
rights and eight provenance groups remain unresolved; matching finite behavior
does not establish release readiness or Native hardware acceptance.

## Observed boundary freeze

Before authoring, the unchanged external observer records 4,408 complete outputs
and all retained hover/toggle/constant outputs. Suppression vetoes both pointer
and delayed-trigger intent; a peek can hold intent even without a pointer.
The acquired boundary is max(0, panelWidth), inclusive at both ends. NaN retains
ordinary comparison behavior; an unacquired pointer uses the existing edge
constant independently of panel width. No observer or assertion is changed to
make this contract pass.

The actual legacy AppShell observer records 22 full states with no page errors.
The existing mobile stack smoke completes all light/dark, normal/reduced-motion
and 320/390/430-width combinations. These use actual Shell components and
synthetic slots, not a real account or native hardware. The copied Shell observer
was first created during the earlier floating-container replacement; both policy
observations use the same current floating container (its metadata phase is
`after`). Its pre-existing footer assertion and reduced-motion scroll finding
remain recorded rather than claimed fixed. Full outputs, immutable observer
hashes and script hashes are frozen in the baseline before this implementation.
The 50 existing targeted policy/geometry/Shell tests pass before authoring.
